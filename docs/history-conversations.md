# 历史对话需求与接入边界

## 用户故事

| 场景 | 验收标准 |
| --- | --- |
| 查看历史对话 | 完整工作区侧栏与小窗菜单均显示“历史对话”，可点击恢复会话。 |
| 删除历史对话 | 鼠标移入一条记录后出现删除按钮；点击后弹出二次确认。取消不删除，确认后立即移除；删除当前会话时切换到另一条或新建空会话。触屏设备始终显示删除按钮。 |
| 账号保存 | 同一已登录账号跨浏览器登录后可读取自己的会话；退出登录或切换账号后，不能看到上一个账号的对话。服务端按已验证身份决定记录归属。 |

## 当前实现

- 历史对话交互与删除确认已在页面实现，现阶段仍使用浏览器 `localStorage` 保存。附件只保存名称、类型和大小，不保存文件内容。
- 当前官网集成只通过 `postMessage` 传递用于展示的昵称、脱敏手机号和可选 ID；它不提供可由客服服务端验证的登录会话。因此不能据此把历史记录安全地写入“已登录账号”。
- 本地预览使用一份服务端测试 Token 读取测试账号资料，不能作为多用户会话身份。

## 账号保存接口需要的能力

1. 客服服务端能够验证官网用户当前登录态，或使用官网已有的带鉴权历史会话接口。用户 ID 必须来自服务端验证结果，不能直接信任浏览器传入的 ID。
2. 提供按当前用户读取会话列表与内容、创建或更新会话、删除会话的接口；删除接口必须检查记录归属。
3. 首次接入时不自动把同一浏览器的旧本地记录上传到账号，避免把其他登录用户留下的内容误归属。若需要迁移，应由用户确认要导入的记录。
4. 退出登录时清除页面内存中的账号会话；再次登录后从服务端重新加载。接口失败时明确提示同步失败，不将本地保存说成“已保存到账号”。

## 待提供信息
