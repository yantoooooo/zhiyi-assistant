# 优惠券结算接入

## 目标与用户故事

本地测试账号在“订单结算”中查看当前商品可用的优惠券，选择后看到接口重新计算的优惠金额和应付总价；创建测试订单时沿用同一张券。

- 作为客户，我希望知道哪些券适用于当前选购商品，并能选择其中一张。
- 作为客户，我希望选券后看到服务端核算的最终金额，避免页面自行计算出错误价格。
- 作为客户，我希望下单时使用的券与刚才看到的报价一致；券失效或金额变化时先回到结算页确认。

## 接口与流程

1. `GET /zy/cart/total` 返回 `ticketList`、已选 `ticketIds`、`yhPrice` 和 `totalPrice`。结算页只展示该购物车报价返回的可用券；商品详情页的 `queryProDetailTicketList` 不作为整单适用性依据。
2. 用户选择一张券后，再次调用 `GET /zy/cart/total?ticketIds=...`。界面只展示接口返回的优惠和总价。未手动选券时使用接口自动选择的券；测试接口在省略 `ticketIds` 时可能自动选券。
3. 创建订单前以相同 `ticketIds` 再次核价；金额变化或券未被接口确认时阻止提交。核价一致后在 `POST /zy/pay/createOrder` 中传 `ticketIds`。
4. 商品数量变化时清除手动选择，重新查询整单可用券。

## 范围与限制

- 仅沿用当前开发模式的共用测试账号结算。服务器生产模式的测试结算与支付仍关闭。
- 界面一次手动选择一张券；其他促销规则、优惠券组合与“完全不用券”没有明确的接口约定。当前接口即使传空 `ticketIds` 也会自动选择适用券，因此不提供可能失效的“不使用优惠券”选项。
- 优惠金额只取接口 `yhPrice`，券名称、范围和有效期只做展示；页面不推导折扣或叠加规则。
